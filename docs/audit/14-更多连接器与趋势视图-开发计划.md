# 更多连接器与趋势视图 · 开发计划

> 依据：spec 16 Phase 7 门禁（安全架构与数据流说明公开；不要求端口转发；relay 无任意执行能力；性能/费用/来源条款可观察）+ spec 19 §1-§4（A 级第二批：GitHub Releases A/P0-P1、HackerNews A/P1；§4 上线检查）+ spec 08 §8（热度模型：native 指标、不跨平台求和）+ Phase 4 顺延项（GitHub/HN connector）。
> 分支自 main（PR #11 合并后）切出。relay 服务端不在本仓库——Host 侧出站连接/安全会话已在 Phase 1 最小集落地，本批以数据流文档满足门禁第一条。

## 0. 现状事实

- FeedConnector 契约（connectorType/getCapabilities/fetch）+ rss_atom 完整实现（fetchGuard/ETag/429/去重/调度）；FeedConnectorType = rss_atom | custom_json | manual_url。
- FeedItemRepo.addMetric 已支持 (feed_item_id, metric_name, sampled_at) 唯一的指标采样（metric_origin: native_source/derived_estimate）——Phase 4 铺垫，尚无 connector 产生指标。
- FeedSourceRepo.termsUrl 字段就绪；feedServiceHost.addSource 缺省 rss_atom，不支持类型选择。
- RadarView 过滤三态（all/favorites/unread）；无趋势面。

## 3. 纪律

- connector 独立禁用（per-source paused/enabled 已有）；采集日志不含 token/完整敏感查询参数（fetchGuard 既有 + 文档强调）。
- 提交按切片多次提交；提交信息只述改动。
- 每切片：typecheck + lint + architecture:check --changed + 目标测试；收尾跑全量。
